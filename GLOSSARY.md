# Глосарій термінів проєкту

Словник термінів цього проєкту, згрупований за темами. Кожен термін — про те, що він означає **взагалі**, і як саме використовується **в цьому коді**.

## 1. Multitask Learning (ядро роботи)

**Multitask Learning (MTL) / Мультизадачне навчання**
Парадигма, де одна модель тренується розв'язувати декілька різних задач одночасно через спільні параметри. Сенс — задачі діляться інформацією між собою. У нас: клас + H + діаметр в одній моделі.

**Hard parameter sharing / Жорстке розділення параметрів**
Конкретний вид MTL, де частина мережі **фізично спільна** (одні й ті самі ваги), а далі розгалужується на task-specific блоки. Найстаріший і найпоширеніший підхід. Це наш випадок.

**Backbone / Бекбон (енкодер)**
Спільна нижня частина мережі, яка перетворює сирий вхід на абстрактне внутрішнє представлення. У нас — `SharedBackbone`: 4 повнозв'язні шари, які стискають 22 ознаки до вектора з 64 чисел.

**Head / Голова**
Маленька підмережа, прикручена до виходу бекбона, що спеціалізується на одній задачі. У нас три: `class_head` (10 логітів), `h_head` (1 число), `diameter_head` (1 число).

**Shared representation (`shared_repr`)**
Той самий 64-вимірний вектор на виході бекбона. "Стиснутий портрет" астероїда, який мережа вивчила. Корисний не тільки для прогнозу, а й для аналізу — наприклад, t-SNE показує, чи близькі астероїди одного класу опинились поряд у цьому 64-вимірному просторі.

## 2. Архітектура нейромережі

**MLP (Multi-Layer Perceptron)**
Найпростіший тип нейромережі — послідовність повнозв'язних шарів з нелінійностями між ними. Без згорток, без рекурентності. Підходить для табличних даних, як у нас.

**Linear layer / Fully-connected / Dense**
Шар, де кожен нейрон зв'язаний з кожним входом: математично `y = W·x + b`. У PyTorch — `nn.Linear`.

**Batch Normalization (BN)**
Шар, що нормалізує активації в межах батча (середнє ~0, дисперсія ~1). Стабілізує і прискорює тренування, дозволяє брати більший learning rate. У нас після кожного Linear-шару бекбона.

**ReLU (Rectified Linear Unit)**
Нелінійність: `max(0, x)`. Без неї стек Linear-шарів схлопнувся б у один лінійний шар. Стандартний дефолт для MLP.

**Dropout**
Регуляризація: на тренуванні випадково "вимикає" частину нейронів (напр. 30%). Заважає мережі запам'ятовувати тренувальні дані замість того, щоб узагальнювати. На інференсі вимкнено.

**Logits**
"Сирі" виходи класифікатора **до** softmax-нормалізації. Можуть бути будь-якими числами. У нас `class_logits` — 10 чисел, які потім перетворюються на ймовірності.

**Softmax**
Функція, що перетворює N чисел на N ймовірностей (сума = 1). Викликається в Streamlit-додатку для відображення впевненості моделі по класах.

## 3. Тренування

**Forward pass**
Прохід даних через мережу: вхід → бекбон → голови → виходи. Це те, що робить `model(x)`.

**Backward pass / Backpropagation**
Обчислення градієнтів — як треба змінити кожну вагу, щоб зменшити loss. Викликається через `loss.backward()`.

**Gradient / Градієнт**
Вектор похідних loss по кожному параметру. Каже "в який бік і наскільки рухати вагу".

**Optimizer / Оптимізатор**
Алгоритм, що застосовує градієнти до ваг. У нас **Adam** — адаптивний метод, який сам підбирає індивідуальний learning rate для кожного параметра. Дефолтний вибір для більшості задач.

**Learning rate (lr)**
Розмір кроку оптимізатора. У нас 1e-3. Занадто великий — нестабільне тренування; занадто малий — повзе вічно.

**Weight decay**
L2-регуляризація: штраф за великі значення ваг, щоб мережа була "простішою". У нас 1e-4.

**Epoch / Епоха**
Один повний прохід оптимізатора по всьому тренувальному датасету. У нас ліміт 100 епох, але рідко доходить — спрацьовує early stopping.

**Batch / Батч**
Підмножина даних, оброблювана за один forward+backward. У нас 1024 приклади на батч.

**DataLoader**
PyTorch-обгортка, що нарізає датасет на батчі і перемішує (`shuffle=True` для тренувального).

**Early stopping**
Зупинити тренування, якщо валідаційний loss не покращується N епох поспіль ("patience" = 10 у нас). Захищає від перетренування і марного часу.

**Gradient clipping**
Обрізати норму градієнта, якщо вона перевищує поріг (1.0 у нас). Запобігає "вибухам" градієнтів — рідкісним, але руйнівним крокам, що можуть зіпсувати модель за одну ітерацію.

**Learning rate scheduler**
Розклад зміни lr протягом тренування. У YAML вказано `cosine` (косинусне зниження), але **в коді не підключений** — це баг, який слід виправити.

**Checkpoint**
Збережений стан моделі (ваги + стан оптимайзера) у файл `.pt`. Зберігається при кожному покращенні val loss.

**Overfitting / Переобучення**
Коли модель добре працює на тренувальних даних, але погано на нових. Симптом: train loss падає, val loss росте. Бореться dropout-ом, weight decay, early stopping-ом.

## 4. Loss-функції та оптимізація

**Loss function / Цільова функція**
Скаляр, який оптимізатор мінімізує. Чим менший — тим краще передбачення.

**Cross-Entropy Loss**
Стандартний loss для класифікації. Карає мережу за низьку ймовірність правильного класу. У нас для `class_head` з опцією `class_weights`, щоб компенсувати дисбаланс класів.

**MSE (Mean Squared Error) / Середньоквадратична помилка**
Стандартний loss для регресії: середнє від `(передбачення − істина)²`. У нас для H і діаметра.

**Class weights (inverse frequency)**
Множники loss для рідких класів, щоб мережа звертала на них уваги пропорційно нестачі. Формула: `weight_c = 1 / count_c`. Розраховуються в `04_mtl_training.ipynb`, бо рідкісних класів у датасеті ~у сто разів менше.

**Masked loss / Маскований лосс**
Lоss, що ігнорує приклади, де таргет відсутній. У нас через множники 0/1: `(loss * mask).sum() / mask.sum()`. Це ключове, бо діаметр відомий лише для ~10% астероїдів, а викидати решту 90% не можна — вони все одно вчать класифікатор і H.

**Uncertainty weighting (Kendall et al., 2018)**
Спосіб автоматично балансувати кілька лосів у MTL. Кожна задача має тренувальний параметр `log_sigma` ("логарифм невпевненості"), і loss перетворюється на `loss / (2σ²) + log σ`. Задачі, у яких модель невпевнена, отримують меншу вагу автоматично — не треба вручну підбирати коефіцієнти. Реалізовано в `src/models/losses.py`.

**Homoscedastic uncertainty**
Технічна назва типу невпевненості, який моделює uncertainty weighting — одна `σ` на всю задачу, незалежна від конкретного прикладу. Протилежність — heteroscedastic, де σ залежить від входу.

## 5. Дані

**Feature / Ознака / Фіча**
Колонка вхідних даних. У нас ~22 числові ознаки: орбітальні елементи, неозначеності, тощо.

**Target / Label / Таргет**
Те, що модель має передбачити. У нас три: `class_label`, `h_target`, `diameter_target`.

**Train / Validation / Test split**
Розбиття даних на 3 частини: train (вчити), val (підбирати гіперпараметри і моніторити переобучення), test (фінальний неупереджений замір). У нас 70/15/15.

**Stratified split / Стратифіковане розбиття**
Розбиття, що зберігає пропорції класів у кожній частині. Без нього рідкісні класи можуть випадково повністю опинитись лише в одній частині.

**Data leakage / Витік даних**
Коли тренувальні фічі містять інформацію, яку модель не повинна "знати" (бо вона побічно розкриває таргет). У нас `albedo` і `diameter_sigma` дропаються через це — `albedo` обчислюється з H і діаметра, а `diameter_sigma` — це неозначеність діаметра, тобто прямий витік. Список у `DROP_COLUMNS`.

**Imputation / Заповнення пропусків**
Підстановка значень замість NaN. У нас різна стратегія для різних колонок: `neo`/`pha` → 0; `moid` → max + флаг `moid_missing`; `sigma_*` → медіана; регресійні таргети H/diameter → 0 + маска.

**Feature engineering / Інженерія ознак**
Створення нових фіч з існуючих. У нас — `tisserand_j` (параметр Тіссерана), що обчислюється з `a`, `e`, `i` і несе фізичний сенс (відрізняє типи орбіт).

**StandardScaler**
Перетворення кожної ознаки: `(x − mean) / std`, щоб усі фічі мали середнє 0 і дисперсію 1. Критично для MLP — без скейлінгу фічі з великими значеннями домінують.

**LabelEncoder**
Перетворює рядкові назви класів ("MBA", "JFC"...) на цілі числа (0, 1, ...). Зворотна операція — `.inverse_transform()`.

**log1p / expm1**
`log1p(x) = log(1+x)`, `expm1(y) = exp(y)−1`. Використовуються для **стиснення довгих хвостів** розподілу. Діаметр у нас живе в `log1p` під час тренування (бо є і 0.1 км, і 900 км), а Streamlit застосовує `expm1` назад для відображення в кілометрах.

**Parquet**
Колонковий бінарний формат для табличних даних. Швидший і компактніший за CSV, типи зберігаються. Наші `train/val/test.parquet`.

**joblib**
Бібліотека для серіалізації Python-об'єктів у файл. Використовується для збереження `scaler.joblib`, `label_encoder.joblib`.

**Rare classes folding**
Об'єднання маленьких категорій у одну "Rare". У нас HYA, IEO, AST, CEN → "Rare". Без цього класифікатор не може нічого навчитись по класах з кількома прикладами.

## 6. Астрономічна доменна частина

**Asteroid taxonomic class / Таксономічний клас**
Категорія астероїда за орбітою. У датасеті: MBA (Main Belt Asteroid), JFC (Jupiter Family Comet), AMO/APO/ATE (групи Near-Earth), TJN (Trojan), CEN (Centaur), і т.д.

**Absolute magnitude H**
Стандартизована "яскравість" астероїда — яка б була його видима зоряна величина з відстані 1 а.о. від Сонця і Землі. Чим менше H, тим більший і/або яскравіший об'єкт. Регресійний таргет.

**Diameter / Діаметр**
Фізичний розмір астероїда в кілометрах. Відомий лише для ~10% об'єктів (тих, що міряли радаром або тепловим телескопом). Регресійний таргет, тренується в `log1p`.

**Albedo / Альбедо**
Частка сонячного світла, яку астероїд відбиває. Обчислюється з H і діаметра — тому **дропається** як leak.

**Orbital elements / Орбітальні елементи**
6 чисел, що повністю описують орбіту:
- `a` — semi-major axis (велика піввісь, а.о.)
- `e` — eccentricity (ексцентриситет, 0=коло)
- `i` — inclination (нахил до екліптики, градуси)
- `om` — longitude of ascending node (довгота висхідного вузла)
- `w` — argument of perihelion (аргумент перигелію)
- `ma` — mean anomaly (середня аномалія, "де об'єкт зараз")

**Derived orbital quantities / "Астрономічно похідні"**
Величини, що **обчислюються** з основних орбітальних елементів і не несуть нової інформації:
- `q` = `a(1−e)` — перигельна відстань
- `ad` = `a(1+e)` — афельна відстань
- `n` — середній рух (∝ a^(−3/2))
- `per`, `per_y` — орбітальний період
- `moid_ld` — те ж, що `moid`, але в інших одиницях

Усі дропаються — модель і так бачить вихідні елементи.

**Tisserand parameter (T_J)**
Інваріант орбіти астероїда відносно Юпітера: `T_J = a_J/a + 2·cos(i)·√(a/a_J · (1−e²))`. Майже не змінюється навіть після гравітаційних збурень від Юпітера. Корисний, бо різні класи мають різні діапазони T_J (наприклад, кометоподібні орбіти мають T_J < 3). Інженерна фіча — `compute_tisserand`.

**MOID (Minimum Orbit Intersection Distance)**
Найменша можлива відстань між орбітою астероїда і орбітою Землі. Маркер потенційно небезпечних об'єктів.

**NEO (Near-Earth Object) / PHA (Potentially Hazardous Asteroid)**
Бінарні прапори: чи близька орбіта до Землі / чи небезпечна. У нас мапляться Y/N → 1/0.

## 7. Оцінювання моделі

**Accuracy / Точність**
Частка правильно класифікованих прикладів. Погана метрика для дисбалансованих класів — модель може отримати 90% accuracy, передбачаючи завжди "MBA".

**F1-score**
Гармонічне середнє precision і recall. **Macro F1** — усереднення F1 по класах однаковими вагами (карає за погану роботу на рідкісних класах). **Weighted F1** — зважено за розміром класу. У дисбалансованих задачах macro F1 — головна метрика.

**Confusion matrix / Матриця плутанини**
Таблиця "істинний клас × передбачений клас". Показує, які класи модель плутає між собою.

**MAE (Mean Absolute Error)**
Середній модуль помилки регресії. Зрозуміла одиниця виміру (наприклад, "помиляється на 0.3 одиниці H").

**RMSE (Root Mean Squared Error)**
Корінь з MSE. Тих же одиниць, що й таргет. Карає за великі помилки сильніше, ніж MAE.

**R² (coefficient of determination) / Коефіцієнт детермінації**
Скільки дисперсії таргета модель пояснює. R²=1 — ідеальне передбачення; R²=0 — не краще за середнє; R²<0 — гірше за середнє. Стандарт для регресії.

**Baseline / Бейзлайн**
Простіша референсна модель, з якою порівнюєш свою. У нас — LightGBM single-task моделі в `03_baselines.ipynb`. Якщо MTL не б'є бейзлайн — нема сенсу його захищати.

**Ablation study**
Експеримент "що буде, якщо прибрати компонент X?". Наприклад: натренувати ту ж модель з трьома окремими лосами (без uncertainty weighting) і порівняти. У нас поки не зроблено — рекомендується додати.

**LightGBM**
Швидка реалізація **gradient boosting** на деревах рішень від Microsoft. Сильний дефолт для табличних даних — часто б'є нейромережі. Тому і обраний як бейзлайн.

**Gradient boosting**
Алгоритм, що будує ансамбль слабких моделей (зазвичай дерев), кожна з яких виправляє помилки попередніх.

## 8. Аналіз та інтерпретація

**t-SNE (t-distributed Stochastic Neighbor Embedding)**
Алгоритм, що проєктує вектори високої розмірності (наш `shared_repr` з 64 чисел) у 2D для візуалізації. Якщо точки одного класу збираються в кластери — модель вивчила корисні представлення.

**SHAP (SHapley Additive exPlanations)**
Метод інтерпретації: показує, як кожна фіча вплинула на конкретне передбачення. У `requirements.txt` є, але не використовується — варто додати для дипломної.

**Confusion matrix normalization**
У нас нормалізована по рядках — кожен рядок сумується в 1. Показує, на скільки % істинні представники класу X класифікувались як Y. Краще зчитується, ніж сирі кількості.

## 9. Інфраструктура

**Inference / Інференс**
Використання натренованої моделі для передбачення на нових даних. Це те, що робить Streamlit-додаток.

**Streamlit**
Python-бібліотека для швидких веб-додатків. Перетворює скрипт на UI зі слайдерами, графіками і кнопками без HTML/JS.

**Docker**
Контейнеризація — упаковує код, залежності і дані в один образ, що однаково запускається будь-де. У нас `Dockerfile` для розгортання Streamlit-додатка.

**PyTorch**
Фреймворк для нейромереж від Meta. Альтернатива TensorFlow. Усе наше MTL — на PyTorch.

**Optuna**
Бібліотека для автоматичного підбору гіперпараметрів (lr, batch size, dropout...). У `requirements.txt` є, але ще не використовується — потенційний наступний крок.

## Бонус: терміни, які варто розуміти для захисту

**Transfer learning** — натренувати на одній задачі, потім дотренувати на іншій. Не MTL (задачі вчаться послідовно, не одночасно).

**Multi-output regression** — одна модель передбачає кілька регресійних таргетів. Окремий випадок multitask, якщо таргети дійсно різні задачі.

**Joint training** — синонім MTL у сенсі "тренування на спільному лосі".

**Inductive bias** — припущення, "вшиті" в архітектуру моделі. Hard parameter sharing — це inductive bias "задачі мають спільну природу".

**Catastrophic forgetting** — проблема transfer learning, де модель забуває стару задачу при навчанні нової. MTL цього уникає за визначенням, бо вчить все одночасно.
